# Project Reflection

Working on this project helped me understand algorithmic complexity and side channel attacks better. Before putting everything together, some of these topics were difficult to picture just from reading about them. Creating interactive examples made it easier to see how they work and why they can cause security problems.

One part I found interesting was the hash table denial of service example. Changing the number of keys and seeing how they collect in the same bucket helped me understand how an attacker could make a hash table much slower than it should be. The ReDoS example also helped me understand how a poorly designed regular expression can use up a lot of processing time, even with a relatively small input.

I also learned more about side channel attacks. I used to think of security mostly in terms of protecting passwords and preventing unauthorized access. This project showed me that information can sometimes leak through things like timing, power usage, or cache behavior, even when the system is working as intended. The timing attack example made that idea easier to understand because it showed how differences in response time can reveal information.

A challenge was deciding how to make the project interactive without making the examples too complicated. I wanted the controls to actually show something useful instead of just changing a number on the screen. I adjusted the examples so that changing the settings would also change the visual explanation or results. I also had to make sure the examples stayed educational and did not run real resource exhaustion attacks.

This project helped me connect the concepts to practical situations. I have a better understanding of why inefficient algorithms can become security weaknesses and why developers need to think about information that might leak through a system's behavior. If I continued working on it, I would add more detailed examples and improve some of the visual explanations so users could explore the concepts in more depth.
